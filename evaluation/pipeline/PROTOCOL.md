# Memory Evaluation v2

人工标注定义 memory_target、read_action、action_description 和 success_criterion，程序不自动猜目标或动作。
Gate 输入生成动作段 `[t, action_end)`，按真实视频 PTS 均匀取 6 帧，不足 6 帧使用全部帧。
内容输入 GT 和生成视频各自的人工稳定段 `[eval_start, eval_end)`，分别按 PTS 均匀取 8 帧，不足 8 帧使用全部帧。
Gate 单次请求只含有序的生成动作帧；动作正确且目标区域可见时 Gate=1，物体有无或是否正确不参与 Gate。
Gate 通过后，每个请求只含一张 GT、一张生成稳定帧，VLM 直接输出三维分数及图像证据。
双方抽帧数量不同时按相对进度配成较多侧的组数，较短侧可复用最近进度帧，所有独立抽帧均参与并记录复用情况。
物体清单按确认的具体物体身份和数量评估，不强制同类别配对；无确认身份的物体不给外观或空间信用。
外观评估可识别物体的细节保真度，空间评估物体关系或内部分区布局，普通“在抽屉内”不额外计空间分。
GT 缺少适用事实时对应维度为 N/A，生成缺失或不可见不能将 GT 适用维度变成 N/A。
每维先跨图片对求平均，再按 temp.config 的 `[weights]` 归一化加权，默认三维权重均为 1。
Gate 失败时 Memory=0 且跳过全部物体 judge，内容维度显示未评估；接口失败或 GT 无效显示错误并不计模型零分。
每个 VLM 请求最多 8 张图片，应用层与 vLLM 服务层均设上限，所有 prompt 都说明任务背景。
V2 与旧版 V1 的打分定义不同，跨版本分数变化不能直接解释为模型能力变化。
程序验证覆盖输入片段、帧数、抽帧、请求角色、JSON 契约与加权计算；VLM 语义判断请通过逐对图片和原始响应复核。

V2.1.0 保留每次 VLM 报告的三维原始分数，并使用同次请求给出的 verified_matches 复算 Inventory F1、appearance_items 复算全部 GT 物体的外观均值，避免模型算术错误；空间仍采用该次图像 judge 的分数并执行 GT 适用性与身份约束。
